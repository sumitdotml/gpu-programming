    What the picture is careful about
    
    
      
      
    • cudaMalloc copies no floats. It reserves GPU bytes and writes one address into M_d. The GPU block holds garbage until cudaMemcpy or a kernel writes it.
      • 
      
    • &M_d is a host address in this matmul() function. The kernel launch passes the value of M_d. In your MatMulKernel the parameter is also named M_d, but it is a separate variable that holds a copy of that GPU address.
      • 
      
    • Host code cannot follow a GPU address. Reading M_d[0] in ordinary host code is invalid. To see GPU floats on the CPU, copy them back into a host block first.
      • 
      
    • Your file has two M_h variables. In matmul_thread_per_col.cu, main() stores the address returned by malloc and passes that value to matmul(). Its parameter M_h is a second host variable with a different & address that holds the same heap address. The diagram draws matmul()'s frame, where M_d is declared too.
